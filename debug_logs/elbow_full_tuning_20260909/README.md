## 500Hz追加記録試行の中止（2026-09-10 05:00）

`../arm_step_20260910_045932/` は開始約1.37秒でROS FB途絶、Disableサービスもタイムアウト。
SWDリセット後、追加リング実装を撤回して基準ELF
`7cd18a5d45413c0c12a0545022a595eacbd8107f163db458f3b857f20250d674`
へ書き戻し・照合。`../arm_step_20260910_050044/` に4台Disableを確認。
肘103.404度、根本0.345度。以後の動作試験は行っていない。

RAM配置の重大な問題を発見（未修正）:
LWIP/Target/lwipopts.h の LWIP_RAM_HEAP_POINTER は0x20048000固定。
通常BSSにはこの領域の予約がなく、基準Debug mapでも
robstride_fb_data_global が0x20045900からサイズ0x4080（末尾0x20049980）で重複。
LwIPはMEM_LIBC_MALLOC=0、MEM_SIZE既定1600なので固定ヒープを使用する。
追加65KBリングで配置が変わり、動作中の書き込みがヒープを壊した可能性が高い。
故障時のRAMは緊急リセットで失われたため、直接の破壊箇所は未確認。
この競合を解消・非動作検証するまで新たな実機駆動を行わない。
tools/read_arm_fast.py は試作用。現行ELFにarm_fast_logは存在せず使用不可。

追記: 上記は05:00時点。後続のヒープ分離修正と高周期記録の復旧・実機検証は
`../lwip_heap_fix_20260910/README.md` を参照。現在はarm_fast_logを復旧済み。
